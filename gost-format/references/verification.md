# Нормоконтроль результата

## Проверка исходника

Проверяй каждый параметр по выбранному профилю, различая обязательное требование, допустимое исключение и локальную настройку. Места замечаний обозначай номером страницы и/или заголовком, для DOCX также индексом абзаца из отчёта.

- Геометрия каждого раздела; размер и ориентация листа; поля, переплёт, зеркальный режим, колонки. Исключения для А3 или альбомных вставок проверяй отдельно.
- Основной текст: фактическая гарнитура, размер, цвет, интервал, абзац; прямое форматирование поверх стилей. У формул, титула, подписей и таблиц собственные правила.
- Состав документа по типу работы; титульные реквизиты; структурные заголовки и уровни разделов; переносы и конечные точки; начало разделов с новой страницы.
- Сквозные страницы и скрытый номер титула; правильные страницы в оглавлении после обновления полей.
- Первое упоминание и размещение таблиц/рисунков, единая нумерация, положение подписей, продолжения многостраничных таблиц. Не отрывай подпись от объекта.
- Положение формул и номеров, пояснения символов, единицы величин, работоспособные перекрёстные ссылки.
- Соответствие списка источников всем отсылкам; достоверные реквизиты; приложения и ссылки на них. Не оставляй демонстрационные измерения и библиографию шаблона вместо реальных данных.

## Помощник DOCX

Запускается Python 3.10+ без сторонних модулей. Параметры по умолчанию проверяют только портретную А4 и поля профиля 7.32. Допуск 0,15 мм учитывает округление twips и не является разрешённым стандартом отклонением.

```bash
python scripts/check_docx.py report.docx --output docx-check.json
python scripts/check_docx.py report.docx --margins-mm 30 10 20 20 --output department-check.json
```

Порядок полей: слева, справа, сверху, снизу. `--paper-mm` меняет ожидаемые ширину и высоту. Коды выхода: `0` — геометрия прошла, `1` — есть расхождения или неполные данные геометрии, `2` — вход не удалось разобрать. Дополнительные предупреждения и непроверенные области остаются даже при `0`.

В JSON есть все разделы и непустые абзацы, включая таблицы. `pPr`/`rPr` и определения стилей даны как исходные свойства XML. Скрипт не вычисляет отображение шрифтов из темы, всю цепочку стилей, позиции объектов, визуальную пагинацию и актуальность полей. Изменения с рецензированием и текстовые блоки требуют отдельного анализа. Не принимай `geometry_status: PASS` за итог нормоконтроля.

## Проверка экспорта

Выполни окончательный экспорт в PDF доступным редактором/компилятором; поля и оглавление должны быть обновлены. Если средства экспорта нет, не устанавливай случайную замену без оценки совместимости; сообщи, что визуальная проверка не выполнена.

Отрендери и просмотри **все** страницы финального PDF. Контролируй пустые листы, обрезанный текст, висячие заголовки, смещение подписей, разрывы таблиц, читаемость рисунков, номера формул и страниц. Контактный лист помогает обзору, но мелкие элементы и подозрительные страницы проверь в полном размере. После правок заново проверь экспорт и все затронутые страницы; при изменении пагинации — документ целиком.

При наличии Poppler команды `pdfinfo`, `pdffonts`, `pdftoppm -png -r 120 report.pdf pages/page` помогают проверить размер страниц, встроенные шрифты и изображения страниц. Фактические названия шрифтов в PDF сопоставляй с профилем, учитывая префиксы subset; наличие похожей гарнитуры не доказывает использование требуемой. Скриншот не подтверждает скрытые настройки исходника, а корректные свойства исходника не доказывают отсутствие дефектов экспорта.

## Вердикт

Для замечания укажи: место, источник и пункт требования, ожидаемое значение, найденное значение, исправление или причину исключения. Используй статусы «проверено», «нарушение», «не применимо», «не проверено». Если остались непроверенные обязательные требования, скажи «оформлено по профилю …; осталось проверить …», а не «полностью соответствует ГОСТу».
