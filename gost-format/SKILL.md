# Строгое оформление по ГОСТ

Создавай или исправляй сам документ и проверяй результат. Если пользователь просит только аудит, выдай замечания без изменения файла. Отвечай по-русски, если пользователь не выбрал другой язык. Основа скилла — [Potato83/GOST-standart](https://github.com/Potato83/GOST-standart); шаблон репозитория не является текстом стандарта.

## Выбери применимые требования

Из запроса и приложений определи вид работы, требуемый формат, стандарт с годом и методичку. Не переспрашивай то, что уже есть в документе или переписке.

- Для лабораторного отчёта по этому репозиторию без иных указаний используй профиль ГОСТ 7.32–2017: Times New Roman 14 пт, А4, поля 30/15/20/20 мм, интервал 1,5, абзац 12,5 мм. Число 14 и выбор гарнитуры — настройки профиля, а не безусловные требования самого ГОСТа.
- Для курсовой, ВКР, диссертации, делового или конструкторского документа сначала установи применимый стандарт и требования организации. Не переноси оформление лабораторной на любой документ. Если это существенно влияет на результат и источника нет, задай один вопрос о виде документа/методичке; пока можно проверить содержание и имеющееся оформление.
- Различай обязательную норму, рекомендацию стандарта, требование методички и выбранную настройку шаблона. При конфликте не объявляй их одновременно выполненными. Применяй явно выбранный пользователем вариант и указывай конкретное расхождение; если выбор не задан и конфликт существенный, уточни только его.

Перед строгим нормоконтролем прочитай [references/standards.md](references/standards.md). Проверяй действующую редакцию и поправки по официальному источнику, когда утверждаешь соответствие актуальному стандарту. Для заданной исторической редакции сохраняй её. Если источник недоступен, используй подтверждённый текст, назови редакцию и ограничение проверки, не выдумывай номера пунктов.

Составь короткий рабочий профиль: `вид документа → стандарт/редакция → локальные требования → параметр → основание`. Поля титула, ФИО, группа, результаты измерений и источники должны происходить из материалов пользователя; недостающее оставляй явно незаполненным в черновике. Не выдавай черновик с пропусками за готовый к сдаче.

## Оформи файл

Прочитай нужную ветку в [references/templates.md](references/templates.md). В `assets/main.tex` и `assets/main.typ` лежат исходные шаблоны репозитория. Копируй их в рабочую папку документа, заменяй примеры и исправляй известные ограничения; не меняй оригиналы скилла при каждом использовании.

Сохраняй исходный формат и содержание, если пользователь не просил конвертацию или редактуру. Для готовой работы соблюдай смысловые роли: основной текст, заголовок, подпись, формула, таблица, список источников, приложение. Массовое применение параметров основного текста ко всем абзацам разрушает оформление. При создании с нуля выбирай формат по запросу; без указания для редактируемой учебной работы предпочитай DOCX, для уже заданного LaTeX/Typst продолжай тот же инструмент.

Для DOCX и PDF используй доступные навыки работы с этими форматами, если они есть в окружении, и их средства рендеринга. Без них допустим прямой разбор OOXML и доступные средства экспорта. Не подменяй запрошенный файл текстом в чате.

Используй стили, автоматическую нумерацию, поля страниц и перекрёстные ссылки. Не выравнивай текст пробелами, не набирай оглавление и номера страниц вручную. Не выдумывай библиографические реквизиты, DOI и даты обращения. Оформление не даёт разрешения менять результаты, дописывать исследования или добавлять фиктивные источники.

## Проверь результат

Пройди [references/verification.md](references/verification.md): параметры файла, структура и ссылки, затем вид всех страниц после финального экспорта. Для DOCX доступен помощник без внешних Python-зависимостей:

```bash
python scripts/check_docx.py /path/to/report.docx --output /path/to/docx-check.json
```

Пути `scripts/`, `references/` и `assets/` отсчитывай от папки этого скилла. Скрипт проверяет геометрию разделов и извлекает свойства для дальнейшего анализа. Его `PASS` относится только к геометрии; шрифт, интервалы, титул, формулы и внешний вид требуют отдельной проверки. Для кафедральных полей передай явно выбранные значения, как описано в справке скрипта.

После исправлений обнови поля и содержание, повтори экспорт и проверь изменившиеся страницы. При отсутствии шрифта, компилятора или средства рендеринга сообщи конкретное ограничение: успешная запись файла не означает проверенную вёрстку. Не называй результат полностью соответствующим ГОСТу при непроверенных обязательных требованиях.

Выдай ссылку на готовый файл, назови использованный стандарт/профиль, кратко перечисли выполненные проверки и оставшиеся расхождения. Подробную таблицу `место → требование и пункт → обнаружено → исправлено/нужно решение` добавляй при аудите, большом числе замечаний или по запросу.
